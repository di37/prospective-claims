# data/raw

Source data exactly as retrieved. Never edited, never regenerated by anything other than the pull scripts. Nothing here is committed: this README and the directory are, the contents are not.

Two sources land here. Earnings-call transcripts come from the HuggingFace dataset named below, pulled by `scripts/00_pull_transcripts.py`. Financial facts come from SEC Company Facts at `data.sec.gov`, pulled per CIK.

XBRL facts are stored as-first-reported. Company Facts serves the current value of a concept including restatements, and a restatement issued after a claim would leak information that was not available when the claim was made.

## Transcripts, and why the text is never redistributed

`RudrakshNanavaty/earnings-call-data`, one file, `episodes.parquet`, about 1.2 GB and 33,362 calls across 685 tickers from 2005 to 2025. The pull writes `transcripts.provenance.json` beside it recording the SHA-256, the row and column counts, and the position below.

The release is tagged MIT. So is `Bose345/sp500_earnings_transcripts` beneath it, and `kurry/sp500_earnings_transcripts` beneath that. None of the three names the vendor the transcripts originally came from, several transcripts still carry a `TRANSCRIPT SPONSOR` line, which is a vendor artefact, and one card tags MIT while also saying "for research and educational use only", which MIT does not say.

A licence tag applied by an uploader does not grant rights the uploader does not hold. The study therefore treats the text as third-party content regardless of the tag:

- The corpus is pulled and never committed.
- No derived artifact carries transcript text. `data/interim/transcript_segments.parquet` holds character offsets, not the segments themselves.
- A released dataset carries claim spans, character offsets, resolutions, and labels, plus a script that rebuilds the text from this source.

That was the project's stated position before the corpus was pulled. The licence chain confirms it rather than changing it.
