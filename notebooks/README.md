# notebooks

Read results and interpret them. Generate nothing.

Tables come from `reports/tables` and figures from `reports/figures`. A notebook may render and save a figure built by a shared builder in `src`, because the figure script renders the same builder to the same filename and the artifact stays reproducible. A notebook may not construct a figure inline and save it, and may not write tables at all.

The reason is provenance. A figure that exists only in a notebook's output cell cannot be regenerated by running anything, and quietly becomes wrong when the results behind it change.

`10_verify_invariants.py` checks both rules and exits non-zero on failure.

| Notebook | Interprets | Built by |
|---|---|---|
| `01_metric_classes.ipynb` | `reference/metric_classes.csv` | `scripts/01_build_metric_classes.py` |
| `02_filers.ipynb` | `reference/filers.csv` | `scripts/02_select_filers.py` |
| `03_filing_dates.ipynb` | `reference/filing_dates.csv` | `scripts/03_build_filing_dates.py` |
| `04_fiscal_calendar.ipynb` | `reference/fiscal_calendar.csv` and `reference/fiscal_quarters.csv` | `scripts/04_build_fiscal_calendar.py` |
| `05_transcripts.ipynb` | `reference/transcript_coverage.csv` | `scripts/05_build_transcript_inventory.py` |

A notebook is numbered to match the script whose output it reads, and reads that table's provenance record alongside it. A gap in the numbering means the table has no notebook yet, not that the notebook was renamed.

If a notebook needs a figure that does not exist, add the builder to `src` and register it in `08_make_report_figures.py`.
